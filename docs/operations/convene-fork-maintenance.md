## 必须保留的行为

### 项目和执行端

- T3 项目与 Convene 模块处于相同抽象层级，一个本地项目可关联多个模块。
- 项目关联模块和 MCP 能力授权分别配置；不可从模块绑定隐式扩大 MCP 范围。
- 添加文件夹／创建／克隆项目后可配置 Convene 与 MCP，后续可在项目设置调整。
- 一个模块可以绑定多台电脑上的多个项目，但给 Web Agent 执行新任务的位置只能显式激活一个。旧会话保持原执行端，离线不自动改派。
- U2 保留项目树、单行会话与各新建入口的明确项目归属。2026-10-11 用户确认尊重上游 Scratch 特殊项目（无项目）交互，不改成 Codex 的“最近”分区。

### 连接体验

- 首次引导顶部始终提供以当前语言自称（English／中文）显示的手动选择入口，不显示额外语言标签或“系统默认”选项，复用现有客户端语言偏好并立即生效；自动识别不能替代手动入口。

- 用户确认 Pull Request/Pull Requests/PR 保留英文。Reasoning、Thinking、Effort 等标题翻译；仅具体思考强度 Low/Medium/High/Extra High/Max/Ultra 保留原文。Service Tier/Standard/Fast 使用“服务等级/标准/快速”，原始 ID 和参数值不变；[Issue #6](convene://issues/zzq/software-factory/t3code/6) 记录界面修订。

- 连接放在初始设置／独立 Convene 设置入口，引导可连接，不放高级设置。项目设置不嵌入连接信息或配对表单；加载中不推断为未连接，确认未配对或离线后仅提供带当前环境的连接设置入口，跳转时关闭项目弹窗。
- 主页使用与设置、分支、用量同排的连接图标，悬停显示状态，点击进入对应环境设置；不独占一行说明。
- 本地开发不强制连接平台；多环境状态与入口保持一致。
- 引导与连接设置共用可编辑地址下拉框。正式安装包必须包含正式平台预置地址，构建时由私有配置注入 `resources/convene-platforms.json`，经桌面 bootstrap 同步给本地及 WSL 后端；带预置配置的发行包以包内配置为准，避免遗留验收配置覆盖正式地址；未内置配置的开发包才读取 userdata 同名文件。无配置仍允许自定义输入。实际地址不提交源码、测试、文档或 CI 日志；GitHub Secrets 提供私有构建输入，含地址的安装包仅以加密产物传输，解密后发布至自有下载存储，不能作为明文 Actions 产物公开。此决定替代之前“所有安装包不含地址”的错误约束。相同显示版号的修订必须使用新构建标识和匹配 Web，不能复用旧 Web 构建身份。
- 项目配置分为“模块绑定”和“Convene MCP”两个独立页签，不用网页入口替代绑定概念。参考 Dextra 的项目→模块选择与跨项目 MCP 范围浏览：项目和模块同屏，已选访问范围保留可见；MCP 未启用时也能编辑配置，无需先绑定执行模块。绑定页保留多模块、目录选择与显式“允许网页执行/停止网页执行”；不得照搬 Dextra 的旧单模块限制。
- 项目/模块列表及已选列表的长名称单行省略，保留完整名称悬停提示；列表独立滚动，确认按钮始终可达。
- 平台端的 MCP 配置共用 Token 权限编辑器的完整布局与控件：能力、已选模块、项目/模块选择和读写权限保持一致，不再拼接第二套范围弹窗。模块客户端列表使用同一全高容器及图标行操作，执行位置与激活状态清晰呈现，长名称省略、窄容器换行。
- 界面以名称、状态和操作呈现，不常驻内部解耦/执行选择合同说明。页签复用宿主小尺寸按钮并提供滑动指示与淡入；MCP 范围支持当前项目模块搜索，并对当前筛选结果全选/取消全选及批量 READ/WRITE，保留筛选外及其他项目选择和已有权限，无 WRITE 的模块不因批量操作获得写权限。
- 创建项目后的配置只提供一个主完成操作：有修改时“保存并完成”，保存成功才结束；“稍后设置”保留未保存输入。模块关联与执行位置仍是各自即时操作，不能让一次 MCP 保存覆盖它们。
- 配对链接带 `user_code`，平台页面预填，登录回跳保留；网页仍由用户确认授权。提供复制配对码和配对链接，按平台 interval 自动换领，成功即完成，不要求点击“我已授权”；取消、过期和错误停止当前等待，错误可重试，过期可重新取码。
- 上游产品使用统计永久关闭且不提供开启入口。保留 AnalyticsService 接口便于合并，运行实现为空；不读取 provider 账户标识、不创建统计 ID、不发送 PostHog。移除引导收集提示和设置／搜索的上游隐私入口；旧环境变量不能重新开启。此决定不关闭本地诊断或用户选择的模型／平台请求。

### 模型

- 原始需求是外部工具切换原生 Agent 配置后，T3 显示真实模型。例如 CC Switch 将 Claude 映射到 GLM；需求不限于 Claude。
- 优先消费 Agent 原生配置、模型目录和会话报告。T3 手工添加只作可选补充，不能要求重复配置来替代原生发现。
- `ModelSelection.model=null` 表示跟随 Agent 默认；与项目默认选择为空（未指定）不同。显示名称不能把 null 改写为具体 ID。
- 新会话使用新默认值；旧会话显示自身报告的实际模型，不能因刷新默认配置而更名或改变执行选择。
- 能确定名称就显示实际名称；不能确定时仅显示“默认模型”。不要向用户解释“未报告”等内部探测状态。
- 多个原生别名指向同名模型时显示原 ID 区分；不写 GLM／Claude 特判。
- 升级提示不常驻普通模型列表底部；仅在搜索相关受版本限制模型时提供有用提示。
- Codex 原生预测默认关闭，按实验功能提供；使用目标环境现有稳定版 Codex 的原生上下文、正常配置及 sample/cancel。配置采样率为 0 时不强启，接受建议只写入可编辑草稿。不得承诺第三方免费待遇或完整官方桌面审核等价。

### 架构边界

- 使用上游 V2 编排，不建立平行会话／执行状态机。Convene 接入集中于 bridge、配置、MCP broker 及必要宿主入口。
- Convene 权限按连接管理和项目配置分别裁决；新增上游 RPC scope 不能覆盖 Convene 映射，反之亦然。
- MCP 必须保持项目授权、只读范围和既有生命周期；上游传输变更时连同 additionalServers 一起迁移。
- Codex 恢复继续使用系统原版 CLI，本轮不分发定制补丁或改变既有 managed 选择。相同有效 MCP 配置热重订阅保留资源；未证实新配置生效时按原操作失败并保留原生上下文，不转 fresh-native/摘要续接，不放宽凭据撤销、不新增卸载延迟设置或前台内部状态。
- ACP Registry 的目录刷新与程序安装分开：目录可自动刷新，托管程序仅由用户手动升级，保留活跃会话；客户端新版提醒短时可关闭，后续下载沿用侧栏现有更新图标，Provider 动作继续独立确认。

## 同步上游的方法

1. 固定双方 SHA，在独立工作区正常试合并；保留此前候选与证据，不触碰用户 profile。
2. 按行为合并：上游接口／正确性修复与本文件列明的需求同时保留，不整批 ours/theirs。
3. 模块重构后将中文接到新 owner，提供 host 名等插值，不能为保留翻译恢复旧 GitHub 专用流程。
4. 自动合并的共同修改也可能语义冲突。优先检查 MCP、权限、项目执行目录、模型 null／报告、发行身份。
5. 按受影响范围执行必要测试、类型与构建；原生 UI／实际请求／发行包各自记录证据，不把单元测试当实机推理。
6. 验证后冻结集成候选；发布后 main 接纳实际发行源码与记录，正式 tag 指向打包提交。新包不继承旧包已验收声明。

候选自动质量与打包沿用 `convene-clients.yml`：协调者推送冻结候选后，执行
`gh workflow run convene-clients.yml --repo zhuziqi97/t3code --ref <候选分支>`。
该入口复用同提交的完整 CI，各质量任务与打包 checkout 均核对实际 HEAD；必需任务
缺失、失败、取消、跳过或来源不一致均阻断候选包。完成的运行须保留 run ID、attempt
和 head SHA；queued 或未运行不是通过。它只生成加密候选产物，不执行正式存储发布。
`ci.yml` 也可单独手动运行完整质量；在默认分支尚无其 dispatch 声明时使用前述既有
候选入口，无需先将未验收源码合入 main。实际客户端验收与正式发布仍独立记录。

正式发行先准备自上一有效版本以来的新版公告草稿供用户审阅，批准后再发布安装包、
匹配 Web 与公告。公告须核验详情、列表、通知索引和 Feed；只有包可下载或公告已构建，
不能报告整次发版完成。草稿使用公告工程的 `_drafts`，不得提前进入 `_posts`。

## 2026-10-16 联动修复

- Provider turn 终止时，现有请求收尾同时取消原生审批及原生问题，并同步请求、节点和展示项；异步 message 问题、其他 turn 及已回答请求保留。仅关闭问题会使已取消命令继续阻塞输入框。
- 本机验收数据库与构建磁盘隔离，沿用测试存储约定，保留 fsync / synchronous_commit；不通过增加锁、租约或 Codex 探测超时掩盖磁盘停顿。私有运行信息与验收数据不进入仓库。

## 2026-10-16 首次加载与控制通道

- 分块资源恢复监听放在 bootstrap、动态导入 main 之前；复用已有 sessionStorage 单次重载保护。持续失败仍显示真实错误，不循环刷新，也不自动重放用户操作。上游主入口仍有同样的注册时序，未来合并时按这一行为保留。
- 配置缓存按控制消息顺序写入，但写盘不能阻塞后续 OPEN_DATA_CHANNEL；MCP 的内存配置仍立即应用，刷新完成回执仍等待保存。缓存 worker 与控制读取属于同一连接，任一失败都结束该连接，不留下脱离作用域的后台任务。
- 取消数据请求只启动受连接作用域持有的中断，不在控制读取器等待旧 HTTP 请求清理。平台只读查询可以有限重建连接，发送、审批、取消等业务操作不能随之重放。
- 候选构建共享程序和各安装器共用 bundle 输出的同一版号；Windows WSL 校验应继续捕获版本不一致，不通过改名产物绕过校验。
