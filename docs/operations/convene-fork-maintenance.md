# Convene fork 的需求与合并决策

本文件是 Convene fork 的长期维护入口。记录用户确认的行为和跨模块取舍；schema 与业务 owner 仍定义运行合同，测试和 Git 提交记录实现。更新决策时修改对应条目，不从聊天重新猜测。平台实施计划位于 Convene 仓库 `docs/plan/t3code-convene-integration-plan.md`。

## 产品与范围

- 近期基于 T3 发布 Runner，不等待 Happier；手机、远程主机、自动化为第二期。
- 产品名称 T3 Code for Convene；保持独立应用标识、CLI、协议、profile 和 `~/.convene-code`。不得覆盖上游 T3 用户数据或使用上游更新包。
- main 只跟踪上游，定制在 `codex/convene-integration`。共享分支使用 merge，不反复 rebase。发布、推送、部署独立记录。
- 中文已纳入首版：早期“只提交上游，等合并”的决定已被用户后续要求替代。

## 必须保留的行为

### 项目和执行端

- T3 项目与 Convene 模块处于相同抽象层级，一个本地项目可关联多个模块。
- 项目关联模块和 MCP 能力授权分别配置；不可从模块绑定隐式扩大 MCP 范围。
- 添加文件夹／创建／克隆项目后可配置 Convene 与 MCP，后续可在项目设置调整。
- 一个模块可以绑定多台电脑上的多个项目，但给 Web Agent 执行新任务的位置只能显式激活一个。旧会话保持原执行端，离线不自动改派。
- U2 保留项目树、单行会话与各新建入口的明确项目归属。2026-10-11 用户确认尊重上游 Scratch 特殊项目（无项目）交互，不改成 Codex 的“最近”分区。

### 连接体验

- 连接放在初始设置／独立 Convene 设置入口，引导可连接，不放高级设置。
- 主页使用与设置、分支、用量同排的连接图标，悬停显示状态，点击进入对应环境设置；不独占一行说明。
- 本地开发不强制连接平台；多环境状态与入口保持一致。

### 模型

- 原始需求是外部工具切换原生 Agent 配置后，T3 显示真实模型。例如 CC Switch 将 Claude 映射到 GLM；需求不限于 Claude。
- 优先消费 Agent 原生配置、模型目录和会话报告。T3 手工添加只作可选补充，不能要求重复配置来替代原生发现。
- `ModelSelection.model=null` 表示跟随 Agent 默认；与项目默认选择为空（未指定）不同。显示名称不能把 null 改写为具体 ID。
- 新会话使用新默认值；旧会话显示自身报告的实际模型，不能因刷新默认配置而更名或改变执行选择。
- 能确定名称就显示实际名称；不能确定时仅显示“默认模型”。不要向用户解释“未报告”等内部探测状态。
- 多个原生别名指向同名模型时显示原 ID 区分；不写 GLM／Claude 特判。
- 升级提示不常驻普通模型列表底部；仅在搜索相关受版本限制模型时提供有用提示。

### 架构边界

- 使用上游 V2 编排，不建立平行会话／执行状态机。Convene 接入集中于 bridge、配置、MCP broker 及必要宿主入口。
- Convene 权限按连接管理和项目配置分别裁决；新增上游 RPC scope 不能覆盖 Convene 映射，反之亦然。
- MCP 必须保持项目授权、只读范围和既有生命周期；上游传输变更时连同 additionalServers 一起迁移。

## 同步上游的方法

1. 固定双方 SHA，在独立工作区正常试合并；保留此前候选与证据，不触碰用户 profile。
2. 按行为合并：上游接口／正确性修复与本文件列明的需求同时保留，不整批 ours/theirs。
3. 模块重构后将中文接到新 owner，提供 host 名等插值，不能为保留翻译恢复旧 GitHub 专用流程。
4. 自动合并的共同修改也可能语义冲突。优先检查 MCP、权限、项目执行目录、模型 null／报告、发行身份。
5. 按受影响范围执行必要测试、类型与构建；原生 UI／实际请求／发行包各自记录证据，不把单元测试当实机推理。
6. 验证后快进 main 至此次固定上游，并合入集成分支；新包重新冻结，不继承旧包已验收声明。
