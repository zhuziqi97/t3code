## 我们的 PR 如何处理

GitHub 读取查询 `repo:pingdotgg/t3code is:pr author:zhuziqi97` 仍返回 0。
现存的是自己的功能分支/补丁，不是等待审阅的上游 PR；#11919/#16087/#16673 等参考 PR
属于其他作者，关闭未合并的分支不能由我们直接“更新 PR”。

1. `codex/fix-codex-import-titles-v2` 保留为 `.25` 来源，不 force-push、rebase 掉已发行历史。
   在新上游短分支只提取剩余问题：保存名称优先与旧标题重导修复可形成分别可审阅的范围。
   #20278 已完成的过滤不再重复提。已关闭的 #14906 曾包含 index 与历史修复的大范围，
   故新贡献先明确剩余范围，而不是重投旧大 diff。
2. U1/U2 的产品方向先确认。U3 将 Antigravity 小修与跨 Driver 的原生模型合同分开；
   生命周期从夹带 Convene 的分支提取通用 owner，不能整分支提交。
3. 资源恢复、审批收尾、通知分别是独立问题，继续在 #15/#16/#17 跟踪；发现上游等价修复
   就改用它并关闭重复回馈，不为了保留自己的提交强留实现。
4. 当前没有对上游发 PR/评论的授权，本轮不发送、不推送、不合并生产。今后贡献按当时
   CONTRIBUTING 的范围要求和单一问题规则处理。
